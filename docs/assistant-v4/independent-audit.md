## 1. Executive Audit Findings Summary

Passing the initial 34 V4 tests and `100/100` mock benchmark **did NOT equate to production readiness**. The independent audit identified **14 concrete defects and test-integrity gaps** (3 Critical, 6 High, 5 Medium) across concurrency, routing, security, database safety, and test claims — including a **module circular import**, **V2/V4 double notification conflicts**, an **approval TOCTOU race & rolled-back attempt lockout bug**, a **private KB document IDOR**, **ignored quiet hours / category filters**, **unwired features (`DigestSchedulerV4`, `proactive_investigation`)**, **canonical base64url signature malleability**, and **pre-existing live SQLite schema drift (`0003` vs `0004` tables)**.

Every code defect discovered in V4/session-token paths has been **fixed and covered by new adversarial regression tests** during this audit; external operational items (live DB migration, Watchdog external URL, live Zalo soak, and automated retention cleanup) are cleanly documented as deployment gates.

## 4. Residual Architectural Risks (Accepted with Guardrails)

1. **Free Upstream Model Latency (`7–20s/turn`) & Availability:** Mitigated by ADR-01 (deterministic alerting never waits for LLM) and `CircuitBreaker` (3 failures → fallback to slash commands).
2. **Quota Counting on Enqueue vs. Zalo Provider Rejection:** `QuotaGovernorV4` counts units on enqueue to avoid asynchronous race overruns across concurrent claims, and `OutboxV4Service` falls back to `dashboard_inbox` on `CAP_REJECTED` so failed external quota never hides alerts. However, provider-confirmed usage (`provider_confirmed: false`) remains an estimate until compared against live Zalo Bot Platform counters.
3. **Database Retention Growth:** No background cron prunes aged `v4_event_store`, `v4_delivery_attempts`, `v4_message_inbox`, or `v4_chat_messages` rows yet (~`975 bytes` per event+outbox pair measured). Must be added or scheduled cleanly after Stage 3/4 soak.
