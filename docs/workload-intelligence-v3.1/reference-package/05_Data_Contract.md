# Data contracts — version 1 (target, not existing legacy wire format)

The schemas in `contracts/` and fixtures in `fixtures/` are executable acceptance baselines (JSON Schema Draft 2020-12). Implement typed Pydantic response models and export/compare their OpenAPI schema; generate or maintain checked TypeScript types. Avoid a second runtime schema system. All new read endpoints require server-side admin authorization and existing authenticated BFF routing; retain old array endpoints and consumer semantics. G0 confirms actual route prefix. Example canonical endpoints: GET `/jobs/snapshot`, `/jobs/analytics`, `/jobs/history`, `/jobs/events`, `/jobs/{identity}/detail` under existing v1/BFF. Register static routes before wildcard/dynamic routes. No new AI endpoints. If a schema change is genuinely needed, record ADR, update schema+fixture+tests and get review; don't silently drift.

## Contract conventions
- `schema_version=1` for new read envelopes. Reject unsupported version explicitly in frontend, show safe error/previous known data, no unsafe coercion. Use UTC RFC3339 timestamps, integer bytes and seconds, null for unknown; no NaN/Infinity; enums defined in schema. Scope IDs canonical, null = no filter. All response fields in schema required except explicitly optional. Legacy converters map camel/snake case based on source audit and preserve legacy outputs. `snapshot_id` unique per normalized observation set; source timestamp(s) and received time distinguish collection/transport. Last success only advances on actual successful sample; partial source failure doesn't wipe other data. Each node has quality and observation time. `quality.expected_*` from authoritative inventory or null; `fresh_*` actual fresh observations. Snapshot `workloads` full authorized bounded root list for entity scope (not table search/pagination). `max_snapshot_rows` initial 2000; if above cap return explicit 422/413 with narrower-scope guidance or separately reviewed paginated V2 contract with full-scope server KPI; never truncate silently. UI table pages the complete bounded snapshot (25/50/100), no independent count from page. Diagnostics raw separate legacy query, not mixed into KPI.
- For no fresh roots because sources unavailable, counts null; for partial with at least one fresh source, observed counts only, last-known separately. When fresh source has confirmed empty workloads, valid zero. When only stale rows present, `observed_workloads=null`, `last_known_workloads` from stale roots. Freshness of GPU independent from workload collector; don't infer process coverage from GPU coverage. Snapshot quality PARTIAL if one or more requested sources unavailable; all unavailable error/offline/stale as appropriate. Rows with non-FRESH quality not counted as observed. `device_vram` is device scope, not group/member/search; unknown reconciliation must not produce negative free. `gpu_association_unknown` and `unmapped_member_workloads` explicitly counted among fresh rows. `warnings[]` sanitized codes and messages. IDs must not contain raw secret material.
- `analytics` response returns range `[from,to)` and `bucket_seconds`, per series metric/entity/unit/aggregation, `coverage_ratio` and points (ts,value,quality). No upsampling beyond actual sample resolution. Null gaps; no connected line across missing observation. Capability status SUPPORTED/PARTIAL/UNSUPPORTED/NO_DATA/DEFERRED with reason. Default 24h, presets 1h/6h/24h/7d/30d; custom <=30d UI and <=90d server initial, max 20 series, <=600 points per series (choose coarser compatible bucket), max 100 paginated rows, bounded DB timeout. Query validation 400/422; 401/403 auth; 409 stale/changed target; 503 if entirely unavailable without usable last-good. Valid partial response 200 with explicit quality. Scope and principal included in cache key; clear on auth identity/role/epoch change, discard stale in-flight response after switch/logout. Avoid shared public HTTP caching (`private/no-store` as appropriate). History cursor opaque, signed/validated and bound to authorized scope/range/filter/order; stable keyset `(last_seen_at,id)` or documented equivalent; never offset across changing live snapshot. Event history keyset `(occurred_at,id)`. Search length <=200, allowed sort enums only, no user SQL fragments.
- `history` returns observed stable identity and first/last seen, observed seconds, status and evidence; never infer exit code from missing sample. `events` returns verified evidence/audit only, redacted message, correlation id nullable; no new notification event emission. History V1 read existing telemetry; if identity/host/coverage ambiguous, report unsupported and no fabricated record. V2 capture only if existing non-Zalo writer proven safe and separately approved.

## Action contract (G5 before G6)
Do not expose new controls until G5 security tests and G6 activation tests pass. Keep current legacy route and API behavior unchanged until reviewed cutover. Reuse existing controller. New action adapter requires server-side authorization, current boot/PID/start ticks/UID/container and target nonprotected; old/unknown agent capability -> disabled. Validate again immediately before signal using pidfd, fail closed on unsupported safe mechanism for new path; don't use numeric PID fallback. Check each descendant independently, no negative PGID signal. Reason required and bounded, explicit confirmation; SIGKILL typed target confirmation, no bulk, no automatic escalation. Never send production signals in development/test.

Prefer reviewed existing operation registry if available; otherwise new write path requires atomic operation key bound to principal+action+identity+parameters. Same key/same payload returns existing result, changed payload => 409. Same target/action in-flight => conflict or existing operation; lock/transaction across worker processes (not only in-memory lock); timeout/ambiguous delivery => UNKNOWN, no automatic retry of signal; reconcile verified observation first. If durable idempotency/lock cannot be implemented within scope, keep new controls disabled and document blocker. Operation response schema preserves action, status, verification, remaining/skipped descendants, message, correlation_id, action_id, executed_at. Only verified TERMINATED/KILLED with no remaining/skipped errors counts as success; PARTIAL/TIMEOUT/UNKNOWN/FAILED never green success. Audited denial/result; redact command line/secrets. On stale/role change, invalidate action/drawer and refetch; no optimistic deletion.

## Fixture conventions and invariants
Fixtures are synthetic tests, not production telemetry. `healthy.json`, `partial-coverage.json`, `offline-node.json`, `stale-snapshot.json`, `empty-workloads.json`, `multi-gpu.json` and analytics/history/events/action fixtures must validate against schemas and cross-field checks in `tests/validate_contracts.py`. Verify distinct identities, exact full-list KPI counts, composition total, coverage bounds and expected inventory, VRAM denominator consistency, null semantics, interval bounds and partial action results. JSON Schema cannot enforce all cross-field constraints; invariant tests mandatory. Do not use a fixture in production code. Use old sample DTOs separately for differential legacy tests.
