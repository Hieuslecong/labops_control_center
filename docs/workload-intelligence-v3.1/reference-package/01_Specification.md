## 6. Metric normalization and data quality
- Use explicit `_bytes` for new API; legacy `Mb` fields appear to be MiB due to division by 1024; audit source unit (NVML MiB vs MB, backend GB vs GiB) before conversion. UI GiB for binary units, GB for true decimal only. Never silently reinterpret legacy unit. Maintain old API unchanged; adapter converts based on verified contract.
- CPU utilization: source basis (`per_core_percent`, `host_capacity_percent`, `unknown`); may exceed 100% per-core, do not clamp. Do not use progress bar percentage when denominator unknown. Distinguish instantaneous vs average interval.
- RSS tree sum != unique memory. Label “RSS cộng dồn” and tooltip shared pages may be counted more than once. PSS optional read-only bounded collection for selected tree, permission/timeouts, missing PSS stays null, no RSS substitution. cgroup memory.current is workspace total incl categories/descendants; never sum both workspace and child PSS. Avoid scanning smaps for every PID every 10s. No security capability grants for new metric; unsupported if permission denied.
- GPU per-device vs per-process: device framebuffer usage from authoritative collector; process memory on PID-device basis if supported. Existing tree representative UUID is not enough for per-device attribution. Distinct `(node, boot, pid, start_ticks, gpu_uuid)` key, avoid duplicate root+child aggregation. Unknown device/unattributed memory visible. Reconcile only same sample/device/unit; if aggregate exceeds device used, label inconsistency (rounding/timestamp/etc), don't make negative free or normalize away error. Device free = total−device used only when valid, not allocatable capacity.
- Taxonomy preserve `classification`/`attribution` legacy. Add `workload_kind` (TRAINING/INFERENCE/NOTEBOOK/GENERAL_COMPUTE/MONITORING/SYSTEM/OTHER/UNKNOWN), `kind_confidence`, `kind_evidence` and separate `gpu_associated` nullable. Explicit monitoring executable exact basename (`gpustat`, `nvidia-smi`, `nvtop`) unless stronger evidence shows otherwise; don't match arbitrary substring in unrelated paths. Python alone -> GENERAL_COMPUTE or UNKNOWN, not verified training. Existing verified attribution means recognized workload, not proof of AI. Do not hide user monitoring silently: classify separately, expose toggle. Regression for torchrun/accelerate/DataLoader, notebooks, python scripts, VS Code helpers, protected agents, same username prefixes, GPU association and multi-GPU.
- Quality per source, node, metric: FRESH (UI label Live), STALE, OFFLINE, NOT_CONFIGURED, UNSUPPORTED, NO_DATA, ERROR, UNKNOWN, PARTIAL (aggregate). Distinguish transport and metric support. Include `observed_at`, `received_at`, `last_success_at`, expected cadence, age, coverage, error_code sanitized. Proposed live stale > 3 expected intervals (configurable, audit actual cadence), historical gaps > 2 expected sample intervals not bridged. Last good data may be displayed with stale indicator; disable destructive controls on stale target. Source failure never sets zero or advances last successful timestamp. Inventory expected count independent of online list. Fresh complete empty list is valid zero only.

## 8. Historical analytics and lifecycle
Existing table `telemetry_history_samples` has indexed host/time and JSON payloads. Query read-only, bounded time, no changes to existing Zalo sampling. Verify real row count, earliest/latest, source, coverage, GPU schema, stale samples and host mapping. Existing normalization may default missing host to workstation, fallback ID to PID, missing VRAM to 0; historical records with uncertain identity/host cannot support exact accounting. No backfill based on assumptions. Existing snapshots have jobs_json lacking per-job CPU/RAM; C07 per-workload unavailable unless later capture verified. Prefer host metrics/VRAM/history that are already present. Use explicit `source_version` or documented compatibility reader; don't depend on worker imports. Read shared models only; additive schema for workload-specific observations only if needed and approved through existing migration system, never duplicate all host telemetry. No changes to the AI module. If independent collection necessary for PSS/identity/lifecycle, reuse existing Go collection/cache and existing non-Zalo scheduler if present; otherwise defer and document scope; do not silently add daemon or competing collector.

Identity: node stable ID + boot ID + host PID + start ticks + full container identity where available; immutable workload ID derived/versioned server-side. Existing v1 ref compatible reads; v2 destructive path must verify current boot; if no trustworthy boot ID new UI actions must remain disabled; existing legacy action paths are not changed until safety/compatibility review. Don't invent boot ID from wall time. On node reboot no merge of observations. Distinguish first observed vs actual start; process start timestamp requires correct kernel tick conversion, UTC. Track `OBSERVED`, `STALE`, `MISSING_UNCONFIRMED`, `EXIT_CONFIRMED`, `UNKNOWN`; missing after N valid samples may mark not observed, never success/failure without evidence. Offline gap never closes workload. Confirm exit code/oom only from trusted process/cgroup/job evidence; container OOM not automatically individual workload OOM. Store transition evidence, coverage; prevent duplicate transitions and out-of-order overwrite; idempotent upsert. Track observed intervals not unlimited extrapolation. Historical legacy ID with missing boot identity cannot be used for actions.

Accounting: for fresh consecutive samples of one device, valid intervals dt bounded by expected cadence and gap; observed device-hours = sum(dt where defined occupancy condition)/3600; choose occupancy criterion e.g. at least one confirmed process allocation and document. Compute-equivalent device-hours = integral of valid GPU utilization fraction over observed time; optional, separate. Workload-hours = sum observed runtime of workload identities (can exceed device hours when shared). Never allocate per-member device-hours by VRAM. Report observation coverage (%) = valid observed duration / requested duration; for heatmap normalize per bin by observed duration/count; unknown bins null. No double counting overlapping intervals. Distinguish allocated quota from actual use.

Storage strategy: measure row counts/sizes with read-only aggregate queries; start with indexed queries and cache; only after measured bottleneck add scoped materialized summaries or table/rollups, additive migration. Proposed retention for new workload observations 7d raw, 30d minute summaries, 180d 15-min, 365d daily/verified events, adjustable; do not change retention/deletion of existing shared history or audit without explicit approval. Bound query cost and ingestion rate; no indefinite JSON growth or uncontrolled writes.

## 9. Performance and refresh architecture
- Existing global telemetry query and page use same key; verify actual network call counts before changing. One canonical snapshot owner/query, shared cache, no per-chart polling. Remove double fetch in manual refresh; use try/finally and abort on scope change. Keep last successful per source and expose partial failures. Do not break global header/sidebar or researcher route. Skip background tab polling where possible; global shell may still need telemetry. Keep previous data during revalidation; no flicker or reset selection. Limit concurrent fetches and cancel superseded requests. Charts lazy mount, no costly formatting per tick, memoize based on sample ID and scope. No websocket migration unless evidence demands.
- Initial targets (staging, not guarantees): p95 live snapshot ≤500ms warm cache; common 24h history ≤1s, 30d ≤2s; initial useful UI ≤2s under stated network/device; measure with 1/5/10 concurrent admins and 5/100/1000 synthetic rows, report collector CPU/RAM/query count. No regression of existing workloads. Do not run heavy load on production. Compare before/after same fixture/hardware. If targets unmet, quantify and gate release rather than fake pass.

## 13. V3.1 release decisions
- Historical V1: read existing shared history only, verify field semantics/coverage. Show scope chips. Use canonical IDs and historical group-at-observation where verified; current-group view must be labeled.
