# LabOps Workload Intelligence V3.1 — Data & Telemetry Capability Matrix

Verified against real repository sources and read-only production SQLite snapshot (`2026-11-25`, `4,058` samples per host across `workstation` and `track`).

| Panel / Metric ID | Tab | Capability Status | Proven Source / Field Basis | Explicit Limitation / Unavailable Behavior |
| --- | --- | --- | --- | --- |
| KPI 1–5 (`observed_workloads`, `gpu_associated_workloads`, `observed_members`, `device_vram_*`, `gpu_coverage`) | Overview | **SUPPORTED** | Go Agent `/api/v1/agent/processes`, `/api/v1/agent/gpus` (`nvidia-smi` MiB -> bytes) | Returns `null` (displayed as `—`) when `fresh_workload_nodes == 0` or `gpus` offline; `track` offline yields `1/4` coverage (`PARTIAL`). |
| KPI 6 (`attention_count`) | Overview | **PARTIAL** | Computed from verified live snapshot anomalies (`OFFLINE` nodes, `STALE` sources, VRAM reconciliation mismatch) | Explicitly scoped to verified snapshot conditions rather than unrelated incident inbox counts. |
| `C01` GPU utilization trend (%) | Overview | **SUPPORTED** | `telemetry_history_samples.gpus_json[].utilization_gpu` | Null gap emitted across `OFFLINE` samples and gaps `> 2x` cadence; `track` has `OFFLINE` history only (`NO_DATA`). |
| `C02` Device VRAM capacity donut | Overview | **SUPPORTED** | Fresh `gpus[]` authoritative `vram_used_bytes` / `vram_capacity_bytes` | Unaffected by member/group/search filters (`DEVICE_WIDE`). Offline GPUs excluded from denominator. |
| `C03` Observed VRAM by member (GiB) | Overview | **SUPPORTED** | Deduplicated root workloads grouped by `member_id` | Reconciled separately (`reconciliation: CONSISTENT | MISMATCH | NOT_COMPARABLE`); unattributed shown separately. |
| `C04` Workload composition | Overview | **SUPPORTED** | `workload_kind` + `gpu_associated` precedence (`MONITORING` -> `gpu_non_monitoring` -> `non_gpu_compute` -> `other_unknown`) | Sum strictly equals `observed_workloads`. |
| `T01` Active workload table | Overview & Live | **SUPPORTED** | Canonical snapshot `workloads[]` (single query) | `RSS cộng dồn` explicitly labeled; `PSS` unavailable unless on-demand `/proc/<pid>/smaps_rollup` enabled; Raw mode uses separate admin `/processes` query. |
| `C05` GPU utilization per device (%) | Analytics | **SUPPORTED** | `telemetry_history_samples.gpus_json[]` keyed by `gpu_uuid` | `track` GPUs have no historical samples (`NO_DATA`). |
| `C06` GPU memory history (GiB) | Analytics | **SUPPORTED** | `telemetry_history_samples.gpus_json[].vram_used_mb / 1024` | Null gaps on missing/offline samples. |
| `C07` Host CPU / RAM small multiples | Analytics | **PARTIAL** | Host `cpu_percent`, `ram_used_gb` supported (`telemetry_history_samples`) | **Per-workload historical CPU/RAM is `UNSUPPORTED`** because `jobs_json` does not record per-job CPU or RAM. UI explicitly discloses host-only scope. |
| `C08` GPU temperature (°C) | Analytics | **SUPPORTED** | `telemetry_history_samples.gpus_json[].temp_celsius` | No fabricated universal critical limit when hardware threshold not returned. |
| `C09` VRAM by PID / process | Analytics | **SUPPORTED** | Live snapshot `workloads[]` + `gpu_allocations[]` | Legacy single-GPU aggregate labeled `LEGACY_AGGREGATE`; multi-GPU uses verified `gpu_allocations[]`. |
| `C10` Observed device-hours / compute-equivalent hours | Analytics | **PARTIAL** | Integrated from valid consecutive `FRESH`/`ONLINE` GPU intervals (`<= 180s` delta) | Separate `device_occupancy_hours` (util > 0 or active allocations) vs `device_compute_equivalent_hours`. Never divides by VRAM for per-user hours. |
| `C11` Resource by research group (historical) | Analytics | **UNSUPPORTED** | `jobs_json` has no observation-time `group_id`; `supervisor_assignments` count is `0` | Historical group chart renders explicit unavailable state; `T04` live group summary displays current `member.research_group` labeled clearly as current profile attribute. |
| `T02` GPU process allocation table | Analytics | **SUPPORTED** | Live `workloads[].gpu_allocations` / NVML processes | Multi-GPU rows split per `(pid, gpu_uuid)` with zero double-counting. |
| `T03` Member usage summary | Analytics | **SUPPORTED** | Live `workloads[]` grouped by canonical `member_id` | Individual GPU-hours marked unavailable (`— Chưa đủ attribution`). |
| `T04` Research group summary (live) | Analytics | **PARTIAL** | Current `member.research_group` from verified member records | Unmapped members grouped under `Chưa xác minh nhóm`; clearly labeled as current group, not historical attribution. |
| `C12` & `T05` Observed workload intervals | History | **PARTIAL** | Derived from consecutive `jobs_json` observations (`host_id + job_id + owner`) | Legacy `proc-<pid>` lacks `boot_id`; exit codes unknown (`MISSING_UNCONFIRMED` after gap, never fabricated `EXIT_CONFIRMED`). |
| `C13` Activity heatmap (7×24 Asia/Ho_Chi_Minh) | History | **SUPPORTED** | Normalized observed sample intensity / active count in `UTC+7` bins | Unobserved bins rendered gray (`null`), never zero. |
| `C14` & `T06` Verified events & audit history | History | **PARTIAL** | `AuditEventRecord` (`PROCESS_SIGTERM`, `PROCESS_SIGKILL`, `JOB_STOP`, `V31_ACTION_*`) | Shows verified audit trail; does not infer unrecorded OOM/process exit counts. |
| History V2 durable per-workload collector | N/A | **DEFERRED** | Would require modifying telemetry collector (prohibited Zalo overlap without separate approval) | Deferred per G4 specification; History V1 works cleanly read-only over existing `telemetry_history_samples`. |
